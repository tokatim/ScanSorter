# Оптимизация распознавания

Ветка `perf/ocr-pipeline`, тестовая сборка `0.4.0-perf.1`. Базовая версия: `v0.3.0`, коммит `9300ea0`.

## Результаты на проверенном компьютере

Замеры выполнены 25 ноября 2026 года на Windows x64 с 4 логическими процессорами, в Release, по 3 файла одновременно. Набор: 42 локальных PDF, 80 страниц. Самих документов, имён файлов и прочитанных номеров в репозитории нет.

| Уверенно распознанные номера | 35 | 36 |
| Время CPU | 433.5 с | 308.8 с |
| Суммарные управляемые выделения памяти | 3970.8 МиБ | 1864.9 МиБ |
| Пиковый рабочий набор процесса | 568.2 МиБ | 571.6 МиБ |

В этом прогоне время сократилось на 36.4%, управляемые выделения — на 53.0%. Пиковая память практически не изменилась: уменьшение выделений не означает уменьшение пика в той же пропорции. Все ранее уверенные номера сохранились; один ранее спорный номер распознан правильно и уверенно. Новых неверных уверенных ответов на проверенном наборе не обнаружено. Одно известное неверное имя исходного образца учтено в локальном эталоне.

Это измерения распознавания: просмотр окон проверки, ручной ввод и сохранение копий в этот тест не входят. Для старых номеров без года может по-прежнему потребоваться заполненное поле «Год». Набор ограниченный, по одному запуску каждой конфигурации на обычном рабочем компьютере; эти цифры не являются гарантией для любого архива или оборудования.

На предварительном наборе из 18 документов исходная версия с 3 потоками заняла 95.06 с, оптимизированная — 72.98 с. У оптимизированной версии 2 потока заняли 101.04 с; для этого компьютера оставлены 3 потока. При малом объёме свободной памяти параллельность ограничивается автоматически.

## Что изменено

1. **Замеры этапов.** В `NumberSearchResult.Timings` и локальном журнале видны длительности открытия PDF, отображения страницы, поиска строки, подготовки вырезов, двух распознаваний и сохранения с проверкой копии. Тексты OCR не записываются в журнал производительности.
2. **Быстрая модель только для поиска.** Официальная целочисленная модель `tessdata_fast/rus` находит надпись «в реестре». Прочитанный ею номер не участвует в решении о сохранении.
3. **Область самого номера.** По координатам слова «реестре» выделяется правая часть строки. Исходная модель Tesseract читает её в двух режимах, PaddleOCR — с двумя масштабами. Только четыре одинаковых результата допускают быстрый ответ. Первое расхождение возвращает файл к исходному поиску и полному набору чтений.
4. **Передача пикселей без промежуточного PNG.** Вырезы передаются в Leptonica напрямую. Числовая эквивалентность пикселей и DPI проверена на разных ширинах и масштабах. Исходное JPEG-представление страницы сохранено, чтобы не менять вход распознавания.
5. **Повторное использование.** Масштабированные вырезы и уменьшенная страница используются повторно. Последняя отображённая страница сохраняется до конца обработки документа для попытки поворота, поэтому PDF не отображается повторно.
6. **Массивы нейросети.** Заполнение входного тензора и выбор выходных символов работают через плоские буферы; устранены повторные вычисления границ при масштабировании. Порядок вычислений и правила декодирования сохранены.
7. **Параллельность и освобождение ресурсов.** Число потоков ограничивается CPU и свободной памятью. Частично созданные движки освобождаются при ошибке инициализации.

Полностью убрать JPEG и читать по отдельным горизонтальным полосам тоже проверялось. Первый вариант немного ускорял обработку, но менял результаты и увеличивал пиковую память; второй замедлял обработку. В ветку эти варианты не включены.

## Воспроизведение

Нужны Windows x64, .NET 8 SDK и обычная действующая лицензия программы для OCR-проверок. Тестовые проекты не отключают лицензию.

```powershell
dotnet run --project tests/ScanSorter.Checks -c Release -- --ocr

dotnet run --project benchmarks/ScanSorter.Benchmarks -c Release -- --input "C:/Path/To/PDFs" --output benchmark-results/run.json --workers 3
```

Для фиксированного поднабора передайте `--selection "C:/Path/To/list.txt"` — по одному относительному имени PDF в строке. Старый формат без тома проверяется через `--no-volume true`. Набор должен быть одинаковым для обеих сборок; запускайте сравниваемые процессы по очереди, с одинаковой параллельностью.

JSON-результат содержит имена и прочитанные номера локальных образцов. Храните его в игнорируемой папке `benchmark-results/`, а в Git отправляйте только сводные показатели. Опубликованная сводка: [performance-summary.json](performance-summary.json).

Проверки: 55 успешных — передача пикселей и DPI, границы масштабирования, ограничения параллельности, пустая страница, повторное использование страницы, отмена, форматы номеров и синтетическое OCR обычного, старого и буквенного номера; отсутствие служебных путей активации в Release.

## Дополнительная модель

Источник: [официальный tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast), файл `rus.traineddata`. В проекте он хранится как `rus_fast.traineddata` и встроен в EXE, лицензия Apache-2.0. SHA-256: `e16e5e036cce1d9ec2b00063cf8b54472625b9e14d893a169e2b0dedeb4df225`.

Основная модель чтения номера, PaddleOCR, проверка лицензии и побайтовое копирование исходного PDF сохраняются. Тестовый EXE собирается отдельно от опубликованного релиза:

```powershell
dotnet publish src/ScanSorter/ScanSorter.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:IncludeAllContentForSelfExtract=true -p:EnableCompressionInSingleFile=true -o artifacts/perf
```
